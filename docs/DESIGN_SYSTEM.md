# DESIGN SYSTEM · DSH Desktop 插件管理面板设计 V0.2

## 设计原则与依据

1. **宿主优先**：先通过官方 `cordis-plugin-development` 查询当前 DSH 的真实 Client Slots、Theme tokens 和组件；没查到不臆造。
2. **统一视觉语言，不强制统一布局**：Registry/Skills 更适合列表与筛选；Credits 更适合批次与到期时间；Tasks 适合状态流。
3. **以信息为主**：不使用装饰性渐变/浮光替代有用数据，不用颜色代替文字状态，不把估算/示例伪装成真实积分。
4. **使用语义 Token**：从 DSH 当前主题读色值。下列是项目级语义角色，不是已经确认的 DSH API 变量名。

## 推荐 Token 合约（待 DSH 实机适配）

| 类型 | 建议角色/刻度 | 用法 |
|---|---|---|
| 字体 | 12 / 14 / 16 / 20 / 24 px | 辅助信息、正文、小标题、标题、页面标题 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 px | 基于 4px 网格，跨插件相同 |
| 圆角 | 4 / 8 / 12 px | 输入、卡片、对话框，不滥用大圆角 |
| 语义色 | `surface`, `text`, `muted`, `border`, `accent`, `success`, `warning`, `danger` | 分别映射宿主亮暗主题，不硬编码品牌色 |
| 控件 | 目标尺寸不小于 24×24 CSS px；重要操作优先 44×44 | 遵循 WCAG 2.2 AA 的适用例外规则 |
| 动画 | 100–200ms，遵循 `prefers-reduced-motion` | 用于状态反馈，避免无意义运动 |

## 页面模板

- **全局骨架**：统一标题 + 描述 + 最近一次更新时间；搜索/筛选区；主要数据区；状态/诊断区。
- **Skills Hub**：来源/作用域/版本/指纹状态/差异原因；未知指纹必须给出理由，不允许强制标记“相同”。
- **Credits Center**：账户作用域、领取时间、余额、批次、有效期、证据来源；未知显示 `待核验`。
- **Check-in**：签到行为和积分到账分开显示；允许平台支持的随机调度，失败、验证码和登录失效须可见。
- **SuperAgent**：任务/执行器/审批/结果来源和 Git 隔离；只列出实际支持的 Desktop 能力。

## 必须覆盖的 UI 状态

正常、首次空状态、加载中、刷新、扫描错误、权限不足、客户端未安装、配置已发现但客户端未验证、离线、证据过期、部分成功、操作待确认。**每个状态既有文案又有视觉表达**。

## 视觉评审工作流

1. 使用 `dsh-ui-design` 定义信息架构和验收点；核对现有宿主设计 Token。
2. 使用 **花叔 Design** 探索至少两个真正不同的方向（除非已有固定品牌设计），保留方案来源、截图和选型理由。
3. 根据选定 Design System 实现真实、可操作的 UI，不以孤立静态 HTML 取代 DSH 集成。
4. 使用 **Unslop** 对真实截图做结构/排版/留白/色彩/文案审查，按问题清单改进，不允许改变已确认的产品行为和设计方向。
5. 截图比较（暗/亮、窄/宽）、键盘和焦点顺序、标签和 WCAG 2.2 AA 对比度、减少动态效果、错误恢复，填 `docs/UI_REVIEW_TEMPLATE.md`。
